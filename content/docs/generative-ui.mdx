# Generative UI

Breeze lets a reply carry a rendered widget when a chart, table, or card says
it better than prose. The model emits the **data** for the widget; Breeze does
the rendering.

## The mechanism

An assistant reply can embed a fenced code block:

````text
```breeze-ui
{ "type": "chart", "title": "Revenue", "variant": "bar",
  "data": [{ "name": "Q1", "value": 84 }, { "name": "Q2", "value": 96 }] }
```
````

The fence rides inside the reply's normal text, so it needs no new stream
event, no API change, and no database field. It persists with the message and
re-renders on reload for free.

## The widget types

The grammar is a closed, compile-time whitelist:

| Widget       | What it shows                                  |
| ------------ | ------------------------------------------------ |
| `chart`      | A bar, line, area, or pie chart (single or multi series). |
| `metrics`    | One to six headline numbers, each with a semantic tone. |
| `card`       | A keyed fact with an eyebrow, title, body, and footer. |
| `table`      | A sortable grid of rows and columns.           |
| `comparison` | A side-by-side comparison of named rows.       |
| `tabs`       | Up to six tabs, each holding any leaf widget.  |

Every spec is validated with zod against `lib/genui/schema.ts` before it
renders. An unknown widget type renders as collapsed JSON; nothing is ever
evaluated.

## When a widget appears

The request sends a `genui` field:

- **`auto`** (default). The backend asks a router model whether this turn
  warrants UI. It answers yes only for quantitative data: charts, tables,
  metric cards, and comparisons. Prose, factual questions, and code get a
  plain reply.
- **`on`** (the "Always visualize" toggle). Every reply is generated by the
  stronger UI model.
- **`off`**. Widgets are disabled entirely.

When UI is used, the reply comes from the generative UI model (`gemma3:12b`)
with the widget grammar taught in its system prompt. History is trimmed on
these turns so a long conversation cannot push the grammar out of the model's
context window.

## Rules the model follows

The grammar prompt enforces the same rules documented in `lib/genui/schema.ts`:

- Always write prose too; the widget complements it.
- Use only data the user gave or that appears in the conversation.
- One headline number becomes a `metrics` tile, never a one-bar chart.
- Tones are semantic, not decorative.
- Strict JSON: double quotes, no trailing commas, no comments.

## The context-window trap

Ollama's default window is 4096 tokens, and its OpenAI-compatible endpoint
silently ignores `options.num_ctx`. If the prompt overflows, Ollama truncates
from the front and evicts the system prompt, so the model loses the widget
grammar. Breeze budgets for this:

- The grammar is kept to about 1000 tokens and tested by
  `genui_prompt.test_prompt_budget()`.
- UI replies cap `max_tokens` at 1536.
- History is trimmed before the UI turn.

Raising `OLLAMA_CONTEXT_LENGTH` on the Ollama server relaxes all three, but the
defaults must work unconfigured.
